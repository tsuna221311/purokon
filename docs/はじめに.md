# はじめに — このコードを初めて読む人へ

このファイルは**最初の15分**のためのものです。`README.md` は1万行あって、
これまでに直したこと全部の記録になっています。あれは**あとから調べるため**の

## 1. このアプリは何をするのか

採寸値（バスト・ウエスト・身長など）を受け取って、**縫うための型紙**を出します。

```
   採寸値  →  [ PatternForge ]  →  A4に分割したPDF・SVG・DXF・投影用PDF
                                   ＋ 買い物メモ ＋ 縫う順番
```

コスプレの衣装作りを主な使い道にしています。市販の型紙に無い形（マント・翼・
装甲プレートなど）も、輪郭を描いて渡せば型紙になります。

**この製品が大事にしていること**が1つあります。

> **分からないことは、分からないと書く。**

たとえば「裏地の付け方」は生地と作るものによって変わり、このプログラムは
その情報を持っていません。だから手順書には「ここに手順を書けません」と
書いてあります。それらしいことを書けば、根拠のない指示が型紙に載ります。
新しく何かを足すときも、この線を守ってください。

## 2. 動かしてみる

```bash
pip install -r requirements.txt
python3 app.py            # http://127.0.0.1:5000 が開きます
```

APIキーは要りません（「イラストからAI判定」を使うときだけ必要です）。

テストを走らせる:

```bash
pip install -r requirements-dev.txt
pytest                    # 全部で12分ほどかかります
pytest tests/test_pipeline.py -q      # 一部だけなら数十秒
```

## 4. 1回の生成が、どう流れるか

`engine/pipeline.py` の `_build_from_spec` が本体です。上から読むと順番が
書いてあります。

```
 1. _prepare_settings      設定を確かめ、注記を用意する
 2. （テンプレートを読む）  SVGから輪郭を取り出す
 3. _scale_every_part      採寸に合わせて変形する（3回に分ける）
 4. _finalize_every_part   合印・ダーツ・縫い代を入れて確定する
 5. （注記をまとめる）
 6. _nest_on_fabric        生地の上に並べる
 7. _draw_lining           裏地を引いて、裏地だけで並べ直す
 8. （買い物メモ・縫う順番）
 9. _export_files          SVG / PDF / DXF / 投影用を書き出す
10. _build_fabric_groups   生地を分けたときの、生地ごとの結果
11. （警告をまとめて返す）
```

**3が3回に分かれている理由**が、この設計でいちばん大事なところです。
パーツによっては「相手の出来上がり寸法」に合わせないと決まりません。

```
   1回目  身頃・スカート・パンツ   （自分の採寸だけで決まる）
   2回目  袖・衿                   （身頃の袖ぐり・首ぐりの長さに合わせる）
   3回目  ウエストバンド・カフス   （スカート・袖口の長さに合わせる）
```

画面側（`app.py`）はモードごとに分かれています。

```
   _respond_manual        選んだパーツ構成で生成する
   _respond_illustration  イラストから読み取って生成する
   _respond_multi_size    同じ服を複数サイズぶん生成する
```

どれも `GenerationInputs` という束を受け取ります。関数の冒頭に「このモードが
使う値」が並んでいるので、そこを読めば依存しているものが分かります。

## 5. 追加出力の安全ルール

- `*_specification.pdf` は製作仕様書です。採寸、型紙寸法、裁ち方、構造指定、
  縫製順と未確認事項を同じジョブIDで記録します。画像モードで「自動判定」の
  まま残した構造は「要確認」となり、確認完了まで裁断しないよう明記されます。
- 画像モードは「製作用」と「ラフ確認」を分けます。製作用では襟ぐり、袖、
  ボトム、衿・カフス・フード、開閉、左右構造、内部支持、動作量を人が明示
  しなければ生成前に止まります。ラフ確認では裁断用PDF・DXF・投影PDF・STLを
  配らず、裁断禁止の透かし入りSVGと要確認の仕様書だけを返します。
- 後ろファスナーは開き長を必須入力にし、全幅の後身頃を中心後で左右2枚へ
  分割して、中心後にも指定縫い代を付けます。脇ファスナーは外接矩形の近似線
  ではなく、前後身頃の実際の右脇縫い線へ脇下から指定実長で配置します。
- 後ろホックは個数と中心間隔を入力すると、後身頃を左右へ分割して両側へ
  対応する取付印を出します。後ろスナップはさらに布の重なり量を入力し、
  右後ろへ実寸の持ち出しを追加します。未確定なら製作用データを止めます。
- 左右非対称を製作用として出すには、左側と右側を別々に校正した異なる
  カスタムパーツ輪郭が2件以上必要です。同じ型紙の反転を非対称衣装として
  出力しません。
- ギャザー倍率を指定すると、説明文へ記録するだけでなくスカートの裁ち幅を
  実際にその倍率へ広げ、ウエスト線に寄せ上がり寸法を印字します。縫い合わせ
  検査はギャザーを寄せた後の寸法で行います。
- プリーツは本数だけで推測せず、ひだ深さも必須です。1本あたり深さの2倍を
  型紙幅へ追加し、「折り山」と「折り合わせ」の2本を実寸間隔で印字します。
  同じスカートへのギャザー倍率との同時指定は止めます。
- 前・後ろ中央スリットは対象スカートを中心で左右へ分割し、中心縫い代と
  開き止まりを作ります。左右の脇スリットは、外接矩形ではなく実際の斜め脇線を
  裾から指定長だけたどって印字します。
- ダンス／激しい演技を選ぶと、ぴったり指定との矛盾を止め、標準設定なら
  身頃・ウエスト・ヒップ・袖を「ゆったり」のゆとりへ自動補正します。
- ボーンは前後身頃へ各3本の確定位置を印字します。パニエは柔らかい段フリル式
  またはワイヤー式を選び、段数・丈・段倍率または各輪直径から専用の段パネルと
  ウエストベルトを生成します。各パネルは90cm以下に分割し、パニエ用生地を
  表地とは別に配置・必要量計算します。造形物用の土台は、実寸校正した
  カスタムパーツ輪郭がある場合だけ製作用へ進めます。
- 接着芯は「芯あり」と書くだけではなく、前後身頃・袖・スカート・パンツ・衿・
  カフス・ウエスト帯・フード・カスタムパーツから対象を選びます。縁から0〜5cmの
  控え量を指定すると、実際に写せる芯地裁断線をPDF・SVG・DXFへ共通で印字し、
  個別パーツの裁断指示・接着芯の購入量・縫製手順へも反映します。
- 3D小物は平板だけでなく、利用者が実測した内側半径による一方向の円筒曲面を
  STL/3MFへ出せます。曲率は画像から推定しません。幅または高さに対して半径が
  小さすぎ、180度以上巻き込む設定はエラーで止めます。
- 業者入稿ZIPの `manifest.json` と注文票には、厚み・曲率半径・曲げ方向・
  単位mmを記録します。中央1個・左右2個・上下2個の丸い貫通穴は、直径と
  端から穴中心までの距離を指定して追加できます。輪郭内に収まらない穴は
  エラーで止めます。ベルト用の角丸貫通長穴も、中央1個・左右2個・上下2個、
  長さ・幅・縦横方向・端からの距離を指定して追加できます。丸穴との重なりや
  強度余白不足は出力前に止めます。円形の磁石ポケットは、中央1個・左右2個・
  上下2個、直径・深さ・端から中心までの距離を指定して、上面から掘った非貫通形状を
  出力できます。底厚は0.6mm以上を必須とし、丸穴・長穴との重なりや輪郭外への
  はみ出しは出力前に止めます。クリップ・ブローチピン・可動軸は、強度を
  推測した樹脂部品を自動造形するのではなく、実物を測った穴径と位置で、市販金具用の
  取付インターフェースを生成します。縫い付けクリップとブローチピンは左右2穴、
  可動軸・リベットは中央1穴で、輪郭外や他の穴と重なる場合は出力前に停止します。
- 業者入稿ZIPには `DIMENSIONED_DRAWINGS.pdf` も同梱します。小物1点につき
  A4横1ページで、曲げ前の輪郭、出力メッシュの正面・側面投影、外形寸法線、
  貫通穴・長穴・磁石ポケットの中心座標と径・深さをmmで示します。図上の縮尺は
  実寸ではなく、数値寸法と3MF/STLを正とします。材料別の公差、造形方向、
  サポート位置、実物金具への嵌合と表面仕上げは業者・試作品で確定してください。
- カスタム輪郭は通常の追加パーツに加え、実寸の平面型紙を入力した場合に限り、
  前後身頃・袖・スカート・パンツ・衿・カフス・ウエスト帯・フードの標準型紙を
  置き換えられます。置換対象、必要枚数、平面型紙であること、接続する縫い線を
  確認済みであることを明示入力します。左右2枚が必要なのに片側しかない場合は
  反転を推測せず停止し、実測した袖山／袖ぐり・肩・脇・首ぐり等が不一致または
  測定不能な場合もPDF・SVG・DXFを書き出す前に停止します。
- 装飾・ロゴは配置先と仕上がり幅・高さに加え、透明背景PNG等の画像を任意で
  指定できます。画像がある場合は実際の外周を抽出し、PDF・SVG・DXFに同じ
  実寸線を入れます。外周が型紙の縫い線内に収まらなければ縮小せず停止します。
  色・グラデーション・内側の画線はDXFには持てないため、外形基準として扱います。
- 成人女子・子どもの既定原型に合わない体型や、手持ちの男性・舞台衣装原型を
  使う場合は「採寸指定（専用原型）」を選べます。背幅、胸幅、前ネック幅、
  袖ぐり深さ、前後の肩傾斜、標準ゆとり、胸ぐせダーツ角度の8項目を実測または
  既存原型から転記します。1項目でも空欄なら生成を止め、成人女子の式で補完
  しません。固定した原型値を別サイズへ流用すると根拠が崩れるため、専用原型は
  1サイズずつ生成します。

## 6. 触る前に知っておいてほしいこと

### 出した型紙は、実寸である

A4分割PDFは**1:1の実寸**で刷られます。倍率が狂うと服が作れません。
`engine/pdf_export.py` を触るときは、`scripts/snapshot_outputs.py` で
前後を突き合わせてください。

```bash
python3 scripts/snapshot_outputs.py > /tmp/before.txt
# ...コードを直す...
python3 scripts/snapshot_outputs.py > /tmp/after.txt
diff /tmp/before.txt /tmp/after.txt     # 差が出なければ、出力は変わっていない
```

### 数字は、計算した値から出す

刷る文の中に数字を手書きしてはいけません。同じ数字が計算側にもあると、
必ずどちらかが古くなります（実際に3回起きました）。
`tests/test_round61_one_source_of_truth.py` が見張っています。

出典がそう書いている数字（引用）だけは手書きでよく、その場合は
鉤括弧「」の中に入れるか、理由を書いて登録します。

### 漢字を足したら、フォントを作り直す

型紙PDFには**必要な文字だけを抜き出したフォント**が埋め込んであります。
刷る文に新しい漢字を入れたら、作り直さないと**白紙で刷られます**。

```bash
python3 scripts/build_pattern_label_font.py
```

忘れると `test_the_bundled_font_is_up_to_date_...` が落ちます（3回忘れました）。

### 画面を触ったら、監査スクリプトを走らせる

pytestはJavaScriptを動かせないので、画面の見え方は別に測ります。

```bash
python3 app.py &                                   # 先にサーバを起動
python3 scripts/audit_contrast.py --base http://127.0.0.1:5000
python3 scripts/audit_target_size.py --base http://127.0.0.1:5000
python3 scripts/audit_assembly_map.py              # 刷り上がりの読みやすさ
python3 scripts/audit_projector_scale.py           # 投影用の紙
python3 scripts/audit_measure_guide.py --base http://127.0.0.1:5000   # 測り方が見えているか
python3 scripts/audit_dart_note.py --base http://127.0.0.1:5000       # ダーツの説明が実物と合っているか
python3 scripts/audit_front_zip.py --base http://127.0.0.1:5000       # 前開きが「縫えない」と言われないか
```

`audit_measure_guide.py` は round64 で足しました。「案内をどこに置いたか」
ではなく**スマホの画面で何px見えているか**を測ります。置いてあるのに
画面の外、という形の抜けは、置き場所を読んでも見つかりません。

## 7. 直し方の作法

この製品には、ラウンドを重ねて決まった作法があります。

1. **先に測る。** 「たぶんこうだろう」で直さない。実際に動かして、
   数字か画像で「いま何が起きているか」を出してから直す。
2. **直したら、戻して落ちることを確かめる。** テストを書いたら、
   その手当てを元に戻してみて、**本当に落ちるか**を見る。
   落ちないテストは、何も見張っていません。
3. **推測を出力に混ぜない。** 「たぶん5cm詰めれば入る」ではなく、
   実際に5cmで作り直して入るか確かめてから言う。
4. **見つからなかったものも書く。** 疑って調べて、問題が無かったことも
   記録に残す。次の人が同じ道を2回歩かずに済みます。
5. **自分の失敗も書く。** `README.md` の各ラウンドに「自分で作った失敗」
   という節があります。恥ずかしいことではなく、次の人への引き継ぎです。
