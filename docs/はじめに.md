## 1. このアプリは何をするのか

採寸値（バスト・ウエスト・身長など）を受け取って、**縫うための型紙**を出します。

```
   採寸値  →  [ PatternForge ]  →  A4に分割したPDF・SVG・DXF・投影用PDF
                                   ＋ 買い物メモ ＋ 縫う順番
```

コスプレの衣装作りを主な使い道にしています。市販の型紙に無い形（マント・翼・
装甲プレートなど）も、輪郭を描いて渡せば型紙になります。

**この製品が大事にしていること**が1つあります。

> **分からないことは、分からないと書く。**

たとえば「裏地の付け方」は生地と作るものによって変わり、このプログラムは
その情報を持っていません。だから手順書には「ここに手順を書けません」と
書いてあります。それらしいことを書けば、根拠のない指示が型紙に載ります。
新しく何かを足すときも、この線を守ってください。

## 2. 動かしてみる

```bash
pip install -r requirements.txt
python3 app.py            # http://127.0.0.1:5000 が開きます
```

APIキーは要りません（「イラストからAI判定」を使うときだけ必要です）。

テストを走らせる:

```bash
pip install -r requirements-dev.txt
pytest                    # 全部で12分ほどかかります
pytest tests/test_pipeline.py -q      # 一部だけなら数十秒
```

## 4. 1回の生成が、どう流れるか

`engine/pipeline.py` の `_build_from_spec` が本体です。上から読むと順番が
書いてあります。

```
 1. _prepare_settings      設定を確かめ、注記を用意する
 2. （テンプレートを読む）  SVGから輪郭を取り出す
 3. _scale_every_part      採寸に合わせて変形する（3回に分ける）
 4. _finalize_every_part   合印・ダーツ・縫い代を入れて確定する
 5. （注記をまとめる）
 6. _nest_on_fabric        生地の上に並べる
 7. _draw_lining           裏地を引いて、裏地だけで並べ直す
 8. （買い物メモ・縫う順番）
 9. _export_files          SVG / PDF / DXF / 投影用を書き出す
10. _build_fabric_groups   生地を分けたときの、生地ごとの結果
11. （警告をまとめて返す）
```

**3が3回に分かれている理由**が、この設計でいちばん大事なところです。
パーツによっては「相手の出来上がり寸法」に合わせないと決まりません。

```
   1回目  身頃・スカート・パンツ   （自分の採寸だけで決まる）
   2回目  袖・衿                   （身頃の袖ぐり・首ぐりの長さに合わせる）
   3回目  ウエストバンド・カフス   （スカート・袖口の長さに合わせる）
```

画面側（`app.py`）はモードごとに分かれています。

```
   _respond_manual        選んだパーツ構成で生成する
   _respond_illustration  イラストから読み取って生成する
   _respond_multi_size    同じ服を複数サイズぶん生成する
```

どれも `GenerationInputs` という束を受け取ります。関数の冒頭に「このモードが
使う値」が並んでいるので、そこを読めば依存しているものが分かります。

## 5. 触る前に知っておいてほしいこと

### 出した型紙は、実寸である

A4分割PDFは**1:1の実寸**で刷られます。倍率が狂うと服が作れません。
`engine/pdf_export.py` を触るときは、`scripts/snapshot_outputs.py` で
前後を突き合わせてください。

```bash
python3 scripts/snapshot_outputs.py > /tmp/before.txt
# ...コードを直す...
python3 scripts/snapshot_outputs.py > /tmp/after.txt
diff /tmp/before.txt /tmp/after.txt     # 差が出なければ、出力は変わっていない
```

### 数字は、計算した値から出す

刷る文の中に数字を手書きしてはいけません。同じ数字が計算側にもあると、
必ずどちらかが古くなります（実際に3回起きました）。
`tests/test_round61_one_source_of_truth.py` が見張っています。

出典がそう書いている数字（引用）だけは手書きでよく、その場合は
鉤括弧「」の中に入れるか、理由を書いて登録します。

### 漢字を足したら、フォントを作り直す

型紙PDFには**必要な文字だけを抜き出したフォント**が埋め込んであります。
刷る文に新しい漢字を入れたら、作り直さないと**白紙で刷られます**。

```bash
python3 scripts/build_pattern_label_font.py
```

忘れると `test_the_bundled_font_is_up_to_date_...` が落ちます（3回忘れました）。

### 画面を触ったら、監査スクリプトを走らせる

pytestはJavaScriptを動かせないので、画面の見え方は別に測ります。

```bash
python3 app.py &                                   # 先にサーバを起動
python3 scripts/audit_contrast.py --base http://127.0.0.1:5000
python3 scripts/audit_target_size.py --base http://127.0.0.1:5000
python3 scripts/audit_assembly_map.py              # 刷り上がりの読みやすさ
python3 scripts/audit_projector_scale.py           # 投影用の紙
python3 scripts/audit_measure_guide.py --base http://127.0.0.1:5000   # 測り方が見えているか
python3 scripts/audit_dart_note.py --base http://127.0.0.1:5000       # ダーツの説明が実物と合っているか
python3 scripts/audit_front_zip.py --base http://127.0.0.1:5000       # 前開きが「縫えない」と言われないか
```

`audit_measure_guide.py` は round64 で足しました。「案内をどこに置いたか」
ではなく**スマホの画面で何px見えているか**を測ります。置いてあるのに
画面の外、という形の抜けは、置き場所を読んでも見つかりません。

## 6. 直し方の作法

この製品には、ラウンドを重ねて決まった作法があります。

1. **先に測る。** 「たぶんこうだろう」で直さない。実際に動かして、
   数字か画像で「いま何が起きているか」を出してから直す。
2. **直したら、戻して落ちることを確かめる。** テストを書いたら、
   その手当てを元に戻してみて、**本当に落ちるか**を見る。
   落ちないテストは、何も見張っていません。
3. **推測を出力に混ぜない。** 「たぶん5cm詰めれば入る」ではなく、
   実際に5cmで作り直して入るか確かめてから言う。
4. **見つからなかったものも書く。** 疑って調べて、問題が無かったことも
   記録に残す。次の人が同じ道を2回歩かずに済みます。
5. **自分の失敗も書く。** `README.md` の各ラウンドに「自分で作った失敗」
   という節があります。恥ずかしいことではなく、次の人への引き継ぎです。
